# Eulerase v0.1: scaffold, core, repairs and command line Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the tested core of Eulerase (graphs, trails, contigs, metrics, ORFs, file reading and writing, figure), repair every finding of the spec that lives in that core or in the command line, and ship a command line that does everything the window will later do, so the second plan starts from a proven core.

**Architecture:** One package, `src/eulerase/`, with the modules of spec section 5. The algorithms are carried from the original explorer (named `$EULERASE_SOURCE` below, a read-only export) and re-arranged; parked and dropped code is not carried and the calls into it are cut. Every behaviour is pinned by a test before it is repaired (carried defects as strict expected failures), and every output is checked against an independent oracle.

**Tech Stack:** Python 3.13; networkx, Biopython, matplotlib (numpy comes with it); pytest and ruff for development; setuptools.

**Spec:** `docs/superpowers/specs/2026-11-09-eulerase-v0.1-design.md` (the authority; where this plan and the spec disagree, the spec wins). This plan covers the spec's section 12 steps 1 to 4. Steps 5 to 8 belong to a second plan (see "Left for the second plan").

## Global Constraints

- **The spec is the authority.** A task that cannot be done as the spec says returns NEEDS_CONTEXT; it does not improvise. Parked and dropped features (spec section 3) are not built, however feasible.
- **Independence.** Eulerase imports nothing from any other project and copies nothing about genotype files, variant identifiers, SNP reporting or clinical reports. The runtime dependencies are `networkx`, `biopython` and `matplotlib` and nothing else. Nothing imports `pandas`, `sklearn` or `scipy`. The core (every module except `render`, `cli` and later `gui`) imports neither `tkinter` nor `matplotlib`.
- **The source.** `$EULERASE_SOURCE` is a read-only export of the original explorer. Read it; copy code out by reading and writing files; never edit it. Run it only headless with `MPLBACKEND=Agg`, `PYTHONDONTWRITEBYTECODE=1` and `MPLCONFIGDIR` set to a scratch directory (unset, the source creates a directory inside the export). Never open a window; no `tk.Tk()`. A `PYTHONPATH` takes one entry; a list separated by `:` does not work in Git Bash on Windows.
- **Public repository.** No tracked file, test or commit message holds a user-folder path, a personal name other than the licence holder, an email address, or a path into any workspace. The source is named only as `$EULERASE_SOURCE`. Gate lines are relative to the repository root.
- **Carry, do not rewrite.** A carry task moves the named source lines into the module and changes only what is forced by (a) the module layout, (b) the removal of pandas (rows are tuples of frozen dataclasses), (c) the frozen shapes below, (d) cutting calls into parked code. Algorithms are not changed. A carried defect stays in the code, pinned by a strict expected failure (`@pytest.mark.xfail(strict=True, reason="<finding id>: <one line>")`) which its repair task removes.
- **Tests (spec 8.1).** Each test names the behaviour it guards and fails if that behaviour breaks; it checks against an independent answer (brute force, a direct library call, a mathematical identity), never the code against itself. One test per behaviour; near-duplicates are one parametrized test; no test pins wording or a constant. No test needs a display, the network or the home directory. Every oracle is shown once to catch a wrong answer: a test of the oracle on a deliberately wrong result, in the same file, named `test_oracle_rejects_*`.
- **Task cycle (every task).** Write the tests first, run them and see them fail for the reason the task states, implement the smallest change, run them green, run `python -m ruff check` on the touched files, commit. The report quotes each command and the last lines of its output, and lists separately anything not run. Implementers run only the test files their change touches and the test files that import a changed module (`git grep -l "eulerase.<module>" tests/`), never the whole suite; the gate-runner runs the gates.
- **Determinism (spec 6.3).** A task that writes text names the ordering, number format and line endings it uses from Frozen interfaces and tests the bytes of the file. A task that touches layout tests the coordinates in two processes with different `PYTHONHASHSEED` values on a graph of at least 100 nodes in 2 components.
- **No silent loss (spec invariant 2).** Nothing is removed from the user's data unless the user asked; the result says what was removed. A record or contig that cannot be processed is counted and reported, never skipped silently.
- **Review items (not tests).** A3: no code, help text or document names a simplification the code does not perform; the only two are minimum multiplicity and tip clipping. The help for `--min-count` and `--clip-tips` says they act as error filters only when the input is a set of reads, that on a single assembled sequence a low count marks a rarer k-mer and not an error, and that tip clipping can remove the true end of a sequence. The reviewer of tasks Z1, Z2, AA and AC checks both.
- **Commits.** `type(scope): summary` as each task names. One concern each. The body explains, for a developer reading `git log`, the problem with a concrete case, the change, why this design and which tests pin it. No finding, task or review ids, no brief or untracked file cited, no attribution trailer. Stage files by name; never `git add -A`; never amend, rebase, reset, stash, push or `--no-verify`. Wrap at 72.
- **Shell.** Never `sed -i`. A denied tool call is reported, never retried another way. Bound every command with a timeout; a test that can hang is a defect. Scratch files go in a `mktemp -d` directory outside the repository.
- **Shared files** (`README.md`, `AGENTS.md`, `pyproject.toml`, `LICENSE`, `.gitignore`): only task A edits them. A code-mode task never does.

## Review Focus

The inputs a person is most likely to meet that no finding names. Each has a test in the task that owns the code.

1. Input with lower case, blank lines, Windows line endings and wrapped FASTA lines must give the same k-mers as the clean input (tasks B, E).
2. A record shorter than k, in a set that also has long records, must be counted and reported, not dropped silently, and must not abort the build (task C).
3. A minimum multiplicity high enough to remove every k-mer must give an empty, well-formed result with "not available" metrics, not an exception (tasks G2, H).
4. With both strands, a k-mer equal to its own reverse complement counts twice per occurrence, and N does not defeat the removal of twin contigs (tasks C, G1).
5. A file holding several records of different lengths, a gzip file, and a byte-order mark must all load every record (tasks E, N, O).

## Frozen interfaces

Everything two tasks must agree on. Signatures are `name(args) -> result`. All dataclasses are `@dataclass(frozen=True)`; sequences inside them are tuples.

**Tooling (task A).** Layout `src/eulerase/`, tests in `tests/`, tools in `tools/`. `pyproject.toml`: setuptools, `requires-python = ">=3.13"`, version `0.1.0`, console script `eulerase = "eulerase.cli:main"`, packages found by setuptools' src-layout discovery (`[tool.setuptools.packages.find]` with `where = ["src"]`) and no explicit list of packages, so a subpackage added later is installed without editing the file, dependencies pinned with `==` to the versions installed where the plan was written (networkx 3.6.1, biopython 1.88, matplotlib 3.11.2; numpy 2.5.3 comes with matplotlib and is not listed), optional group `dev` (pytest 9.0.2, ruff 0.16.10). `[tool.pytest.ini_options]`: `pythonpath = ["src"]`, `testpaths = ["tests"]`. `[tool.ruff]`: `line-length = 100`, select `E`, `F`, `I` plus `TID251` with `[tool.ruff.lint.flake8-tidy-imports.banned-api]` entries for `pandas`, `sklearn` and `scipy` (message: not a dependency), so an import in `src/` or `tests/` fails the ruff gate. `eulerase/__init__.py` defines only `__version__ = "0.1.0"`: importing the package has no side effect.

**Errors.** `eulerase.errors.EuleraseError(Exception)`. Every failure a user can cause raises it with one sentence that says what was wrong and what to do (no traceback text, no library message). Anything else raised is a bug.
**Limits (one constant each).** `eulerase.kmers.MAX_KMERS = 500_000`; `eulerase.render.MAX_DRAW_NODES = 400`; `eulerase.analysis.MAX_TABLE_ROWS = 2000`; `eulerase.orfs.MIN_ORF_AA = 10`; `eulerase.analysis.DEFAULT_K = 3`.

**sequence.**
- `Record(name: str, sequence: str)`, a frozen dataclass.
- `parse_records(text: str) -> list[Record]`: FASTA-aware (carried `bio_engine.py:32-51`); with `>` headers wrapped lines join; without headers every non-empty line is a record named `seq1`, `seq2`...; sequences upper-cased, all whitespace removed, `\r` ignored; empty text gives `[]`.
- `parse_kmer_list(text: str) -> list[Record]`: lines starting with `>` are dropped whole; the rest is split on whitespace, commas and semicolons; each token is one upper-cased record named `kmer1`...
- `is_dna(sequence: str) -> bool`: non-empty and every letter in `ACGTN`.
- `reverse_complement(sequence: str) -> str`: via Biopython; N stays N.
- `gc_content(sequence: str) -> float | None`: `None` when `is_dna(sequence)` is false (spec 6.1: GC is offered only for DNA); otherwise (G + C) / (A + C + G + T) with N left out of numerator and denominator, `None` when none of A, C, G, T is present; case-insensitive; one code path; never rounded.

**kmers.**
- `Kmers(items: tuple[str, ...], k: int, short_records: int, duplicates_dropped: int)`; `items` are in generation order (each record's forward k-mers, then its reverse complement's when both strands), or sorted when `unique`.
- `validate_k(k: object) -> int`: the one place k is checked: an `int` (not a `bool`) of at least 2, else `EuleraseError`.
- `from_sequences(records: Sequence[Record], k: int, *, both_strands: bool, unique: bool) -> Kmers`: raises `EuleraseError` for an invalid k, no records, both strands on a non-DNA record, no record at least k long, or more than `MAX_KMERS` k-mers (both strands' k-mers count; the message names the limit as `500,000`); the limit is enforced while generating so an oversized input is refused before the list is built; records shorter than k are counted in `short_records`.
- `from_kmer_list(records: Sequence[Record], *, both_strands: bool, unique: bool) -> Kmers`: each record's sequence is one k-mer; all must have one length; `k` is that length (validated); the same limit and both-strands rules.
- `count_kmers(items: Sequence[str]) -> dict[str, int]`: occurrences, keys in ascending string order.

**graph.**
- `WalkEdge = tuple[str, str, int]` (source node, target node, parallel-edge key); `Trail = tuple[WalkEdge, ...]`.
- `build_walk_graph(items: Sequence[str]) -> nx.MultiDiGraph`: nodes are (k-1)-mers, one edge per occurrence, attribute `kmer`; raises `EuleraseError` for an empty list, mixed lengths or k below 2.
- `node_balance(g: nx.MultiDiGraph) -> dict[str, int]`: out-degree minus in-degree.
- `trail_cover(g: nx.MultiDiGraph) -> list[Trail]`: minimum set of edge-disjoint trails using every edge once (carried Hierholzer with dummy edges).
- `spell(trail: Trail) -> str`.

**assembly.**
- `Contig(id: int, sequence: str, length: int, edges: int, kmer_count: int, mean_multiplicity: float, min_multiplicity: int, gc: float | None, circular: bool, has_n: bool, strand: str)`. `edges` is the number of distinct k-mers in the contig; `kmer_count` is the sum of their multiplicities. `strand` is `"as-assembled"` when both strands are off, `"smaller-of-pair"` when both strands are on and the contig's reverse-complement twin was present, `"unpaired"` when both strands are on and the twin is absent (it was removed by a filter). `has_n` is true when the sequence contains `N`.
- `Metrics(contigs: int, total_length: int, longest: int, shortest: int, mean_length: float | None, n50: int, l50: int, n90: int, gc: float | None, mean_multiplicity: float | None)`: `gc` is `sequence.gc_content` of the concatenated contig sequences; mean multiplicity is the mean of the contigs' `mean_multiplicity`; with no contigs the integers are 0 and the others `None`.
- **Numbers in data are not rounded.** `Contig.mean_multiplicity`, `Contig.gc`, `Metrics.mean_length`, `Metrics.gc` and `Metrics.mean_multiplicity` hold the exact value (`statistics.mean` or the ratio of integers); the carried `round(..)` calls are removed in the carry; `format_cell` is the only place a number is rounded.
- `build_assembly_graph(counts: Mapping[str, int]) -> nx.DiGraph`: one edge per distinct k-mer, attributes `kmer` and `multiplicity`.
- `filter_min_multiplicity(ag: nx.DiGraph, minimum: int) -> tuple[nx.DiGraph, int]`: a copy without the k-mers seen fewer than `minimum` times, and the number of distinct k-mers removed; `minimum <= 1` removes nothing.
- `clip_tips(ag: nx.DiGraph, k: int) -> tuple[nx.DiGraph, int, int]`: a copy, the number of branches removed, the number of distinct k-mers removed (rule of spec row A2).
- `extract_contigs(ag: nx.DiGraph, k: int, *, both_strands: bool) -> tuple[Contig, ...]`: ordered longest first, ties by sequence, numbered from 1 in that order.
- `assembly_metrics(contigs: Sequence[Contig]) -> Metrics`.
- `kmer_spectrum(counts: Mapping[str, int]) -> dict[int, int]`: multiplicity to number of distinct k-mers, ascending.
- `Link = tuple[int, str, int, str]` (from id, from orientation, to id, to orientation); `gfa_links(contigs: Sequence[Contig], k: int, both_strands: bool) -> list[Link]` (carried).

**orfs.**
- `Orf(strand: int, frame: int, start: int, end: int, length_nt: int, length_aa: int, protein: str)`: strand +1 or -1; frame 1 to 3 or -1 to -3; `start` and `end` are 0-based, end exclusive, on the forward strand; `length_nt` includes the stop codon; `length_aa` does not.
- `find_orfs(sequence: str, *, min_aa: int = MIN_ORF_AA) -> tuple[Orf, ...]`: standard genetic code, start codon ATG, at most one ORF per stop codon (the longest: from the first ATG after the previous in-frame stop), an ORF ends in a stop codon (one that runs off the end is not reported), shorter than `min_aa` not reported. Ordered by strand (forward first), frame, start. Raises `EuleraseError` if a letter is outside `ACGTN`.
- `orf_rule_text() -> str`: one sentence stating the start codon (ATG), the genetic code (standard) and the minimum length, built from the constants.

**analysis.**
- `Settings(k: int | None = DEFAULT_K, both_strands: bool = False, unique: bool = False, min_multiplicity: int | None = None, clip_tips: bool = False, input_mode: str = "sequences")`; `input_mode` is `"sequences"` or `"kmers"`; in `"kmers"` mode `k` must be `None` (taken from the k-mers).
- `settings_text(settings: Settings) -> str`: one line, fixed order and wording: `k=5; both strands: yes; set of k-mers: no; minimum multiplicity: none; tip clipping: no` (`yes`/`no`, `none` or the integer).
- `Step(trail: int, step: int, global_step: int, kmer: str, source: str, target: str, key: int, multiplicity: int)`; `NodeRow(node: str, in_degree: int, out_degree: int, balance: int, role: str)` with role `"start & end"`, `"trail start"`, `"trail end"` or `""`.
- `Analysis(settings, k, dna, total_kmers, distinct_kmers, short_records, duplicates_dropped, headline, trails, spelled, nodes, contigs, metrics, spectrum, removed_kmers, clipped_branches, clipped_kmers, orfs, notes)` where `trails: tuple[tuple[Step, ...], ...]`, `spelled: tuple[str, ...]` (one per trail), `nodes: tuple[NodeRow, ...]` sorted by node, `contigs: tuple[Contig, ...]`, `metrics: Metrics`, `spectrum: tuple[tuple[int, int], ...]`, `orfs: tuple[tuple[Orf, ...], ...] | None` (one tuple per contig, same order; `None` when not every letter of the input is `ACGTN`), `dna: bool`, `notes: tuple[str, ...]`. It holds no graph, no coordinates and no matplotlib object. `headline` is `Eulerian circuit · E edges · N nodes`, `Eulerian path · E edges · N nodes`, or `No single Eulerian path · minimum cover = T trails · E edges · N nodes` (parts separated by one space, U+00B7, one space; the source used two spaces on each side). `notes` order: short records, duplicates dropped, minimum multiplicity, tip clipping, both strands; each is a complete sentence; wording is not pinned by tests.
- `analyze(records: Sequence[Record], settings: Settings) -> Analysis`: validates, builds the k-mers, the walk graph and trails, then the assembly graph with, in this order, minimum multiplicity (when set), tip clipping (when on), contigs, metrics, spectrum, ORFs (DNA only). No automatic filter exists. `EuleraseError` for no records and for `min_multiplicity` below 1.
- Tables: `TABLES = ("Edges", "Nodes", "Trails", "Contigs", "Assembly")`; `columns(table: str) -> tuple[str, ...]`; `rows(a: Analysis, table: str) -> list[tuple[str, ...]]`, every cell already passed through `format_cell`. One definition supplies headers and cells for the window and for CSV (the Assembly CSV omits the two text rows, `settings` and `orf rule`, see the Assembly table below).
  - Edges: `trail, step, global step, k-mer, from, to, times seen` (ordered by trail, step).
  - Nodes: `node, in, out, balance, role` (by node).
  - Trails: `trail, edges, sequence` (by trail).
  - Contigs: `contig, length, edges, k-mer count, mean multiplicity, min multiplicity, gc, orfs, circular, has n, strand` (by id; `orfs` is a count, or "not available" when `Analysis.orfs` is `None`).
  - Assembly: `measure, value`, rows in this order: `contigs, total length, longest, shortest, mean length, n50, l50, n90, gc, mean multiplicity, distinct k-mers, total k-mers, removed k-mers, clipped branches, clipped k-mers, settings, orf rule`; `orf rule` is `orfs.orf_rule_text()` when `Analysis.orfs` is not `None`, else `not available`. `csv_text(a, "Assembly")` writes only the rows up to `clipped k-mers`: the `settings` and `orf rule` rows are text, not data, and are shown in the window and by `--metrics` only. CSV files hold data only, so the rule is not repeated in `contigs.csv` either; wherever else ORFs are shown or written it is stated (this row, the GenBank and FASTA output).
- `NOT_AVAILABLE = "not available"`; `format_cell(value: object) -> str`: `int` as digits with no separators, `float` with exactly 4 decimals, `bool` as `yes`/`no`, `None` as `NOT_AVAILABLE`, `str` unchanged. A ratio or mean is always a float.
- `limit_rows(rows: Sequence[tuple[str, ...]]) -> tuple[list[tuple[str, ...]], str | None]`: the first `MAX_TABLE_ROWS` rows and, when cut, the note `Showing 2000 of 5000 rows.` (plain integers); exports never use it.

**io.**
- `detect_format(data: bytes) -> str` returns `"fasta"`, `"fastq"`, `"genbank"`, `"embl"` or `"bare"`, looking at content only (after an optional byte-order mark, after gzip decompression).
- `read_records(path: str | os.PathLike) -> list[Record]`: any supported format, plain or gzip (by magic bytes); never shortens the input; `EuleraseError` for a missing path (always an error, never read as a sequence), a path that is a directory or cannot be opened (one sentence from the `OSError`), an empty file, an unrecognised file, or a parse failure (one sentence, not Biopython's text).
- Writers return text (`str`, `\n` only): `fasta_text(a: Analysis) -> str`, `genbank_text(a: Analysis) -> str`, `gfa_text(a: Analysis) -> str`, `csv_text(a: Analysis, table: str) -> str`. `write_text_file(path: str | os.PathLike, text: str) -> None` writes UTF-8, `\n` line endings, no byte-order mark. `csv_paths(prefix: str) -> dict[str, str]`: table name to `f"{prefix}_{name}.csv"` with names `edges, nodes, trails, contigs, assembly`.
- Text formats (spec 6.2, 6.3): records and rows in the orders above; numbers through `format_cell`; CSV is comma separated, header row first, minimal quoting, `\n` after every row, no settings; FASTA, GenBank and GFA carry `settings_text`: in each FASTA description, in the GenBank `COMMENT`, and as the tag `st:Z:` on the GFA header line. FASTA description: `len=<length> cov=<mean>x gc=<gc> orfs=<count> <settings_text>` until task V, then `len=<length> mean_multiplicity=<mean> gc=<gc> orfs=<count> <settings_text>`; every number through `format_cell` (`not available` for a missing GC or ORF count). GFA 1.0: `H\tVN:Z:1.0\tst:Z:<settings>`, `S\tctg<id>\t<sequence>\tLN:i:<length>\tKC:i:<kmer_count>`, `L\tctg<a>\t<o>\tctg<b>\t<o>\t<k-1>M`. The GenBank writer sets its date field itself to `01-JAN-1980`. The ORF rule text (`orf_rule_text()`) is written in every GenBank record's comment and at the end of every FASTA description (after `<settings_text>`, one space between) whenever `Analysis.orfs` is not `None` (also when the count is 0); when it is `None` the description holds `orfs=not available` and no rule; CSV files hold data only and do not carry it. `settings_text` is a line written into exports, so its exact form is a format.

**render.**
- Palette constants copied unchanged from `$EULERASE_SOURCE/debruijn/graph_core.py:73-84`: `PITH, LEMON, RIND, LIME, ORANGE, EDGE, INK, FUTURE, FUTURE_TXT, PANEL, TRAIL_COLORS, BRANCH`, defined once here.
- `compute_layout(a: Analysis) -> dict[str, tuple[float, float]] | None`: node to coordinates, `None` above `MAX_DRAW_NODES` nodes.
- `draw_figure(fig: matplotlib.figure.Figure, a: Analysis, layout: dict | None, upto: int | None = None) -> None`: draws the walk graph with the first `upto` steps traversed (all when `None`); the title carries `settings_text`; with `layout is None` the figure says why it is empty.
- `FIGURE_FORMATS = ("png", "svg", "pdf")`; `save_figure(a: Analysis, path: str | os.PathLike) -> None` (format from the extension; `EuleraseError` for another one).

**cli (tasks Z1 to AD).** `main(argv: Sequence[str] | None = None) -> int`. Exit status 0 on success, 1 for a failure the user caused (one line on stderr, `eulerase: <sentence>`), 2 for a usage error (also one line). Options, exactly: input `--seq SEQ [SEQ ...]`, `--kmers KMER [KMER ...]`, `--file PATH`; settings `-k INT`, `--both-strands`, `--unique`, `--min-count N`, `--clip-tips`; outputs `--figure PATH`, `--csv PREFIX`, `--gfa PATH`, `--contigs PATH`, `--genbank PATH`, `--metrics`; and `--gui`. ### Task R: Tip clipping that compares multiplicity (repair)

Wave: 9 · Touches: src/eulerase/assembly.py, tests/test_assembly.py, tests/test_assembly_filters.py · After: Q · Mode: code

Behaviour: spec row A2, implemented as the spec's rule, replacing the carried clipper. Opt-in (the setting exists since task H); works on the assembly graph after any minimum multiplicity. A branch is the chain of edges that starts at a node and runs through nodes with one edge in and one edge out, up to the next node that is not like that. A dead-end branch ends where no edge leaves (if it leaves its first node) or starts where no edge enters (if it enters its first node). A dead-end branch is removed only if it has fewer than 2k edges and another branch, dead-end or not, on the same side of the same first node has a strictly higher mean multiplicity over its own edges: a branch that leaves the node is compared only with others that leave it, and one that enters it only with others that enter it. Equal branches are both kept, unless a third is strictly better, when both go. All branches are judged once, on the graph as it stands after any minimum multiplicity, and those that qualify are removed together; a removal never creates a new branch to judge. The result says how many branches and how many distinct k-mers were removed. The acceptance cases are in `test_tip_clipping_follows_the_rule` (task G2); applied literally, the rule removes the first two and the last two k-mers of `ACAAAATA` at k=3, because the self-loop `AAA` is the better-supported rival on both sides of its node.
